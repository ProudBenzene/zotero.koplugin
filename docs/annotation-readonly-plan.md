# Zotero 受管 PDF 批注边界实施计划

状态：2026-10-09 已实施以下代码边界，并通过离线回归及官方 KOReader v2026.07.2 原生模块检查。Kindle 实机验收待完成，v2026.03 的新边界未复验。此前的 `bookmark-fix` 安装包只交付书签归属修复；本次只读版本另行打包。

## 目标与范围

Zotero 是导入批注的唯一权威来源。KOReader 提供离线查看，并允许独立的本地批注；本地批注只保存于 KOReader 文档设置，不上传，也不改写下载的 PDF。

限制仅作用于 `Annotations.managedKey` 已确认的当前账号、附件和规范化文件路径对应的受管 PDF。普通 PDF、其他账号的文件和 EPUB 保持 KOReader 原有行为。书签、阅读进度及已有本地批注保留。

| 操作 | 默认边界 |
| --- | --- |
| 修改或删除 Zotero 导入批注，包括文字、评论、颜色、样式和范围 | 禁止 |
| 查看批注、复制文字、跳转、选词查词 | 保留 |
| 新增、编辑或删除独立的 KOReader 本地批注 | 允许，仅保存于本地文档设置，不上传 |
| 修改下载的 PDF 字节，包括写入高亮、删除或修改内嵌批注 | 强制禁止 |
| 添加和删除书签、保存阅读进度 | 保留 |
| 同步后按合法云端快照新增、修改或删除导入批注 | 保留；离线重开应用最近成功缓存 |

## 第一阶段：保护受管 PDF 原文件

优先建立当前文档实例的 PDF 批注写入限制，而不是只在加载时将 `highlight_write_into_pdf` 设为 false。

- 审查 KOReader v2026.07.2 的全部原生 PDF 批注写入口，包括 `writePdfAnnotation`、批量写入和 `importEmbeddedAnnotations`；核对 `saveHighlight`、`deleteHighlight`、`updateHighlightContents` 的实际调用路径。
- 在当前受管文档实例的实际 PDF 批注写方法阻止写入，并相应禁用重新开启 PDF 写入及批量写入菜单。不修改其他文档的全局偏好或类级方法。
- 原生内嵌批注导入会先删除 PDF 中的原批注，因此在受管 PDF 中禁用这一有文件修改的操作；不允许其在写入被阻止后继续完成一半的流程。
- KOReader 本地批注仍正常写入文档设置。插件下载、缓存校验和云端快照获取流程保持原有契约。

验收：通过原生编辑、批量写入和内嵌批注导入入口均不能修改受管 PDF；测试前后 PDF 的 MD5 相同。本地新增批注可在重开后恢复，基于哈希的文档设置仍能定位。非受管 PDF 的原生写入行为正常。

## 第二阶段：云端导入批注只读

先建立“目标条目是否属于当前附件的 Zotero 导入项”的统一判断，再逐条核对原生修改路径。沿用当前来源标记，并保留书签不被认领为云端批注的保护。

- 覆盖高亮详情、评论编辑、选中文字编辑、颜色和样式修改、范围调整、删除、批注列表以及批量操作。原生直接修改条目字段的路径也要检查，不能仅依赖 `addItem` 或隐藏单条菜单。
- 对云端导入项禁用修改入口，并在实际修改路径校验。混合云端与本地批注的批量操作只处理本地项，界面明确说明跳过的云端项数量。
- 保留导入项查看、评论阅读、复制和跳转。按 2026-10-10 用户调整，标题使用 `Zotero Annotation` 并附带颜色文字，正文不附加修改提示。
- 允许插件按完整有效的云端快照替换导入项，确保云端增改删仍生效；原生迁移、无效缓存保护和离线重开继续可用。
- 只读限制完成后，评估 `extendSelection` 的来源传递适配是否可以移除。仍需保留的排序、匹配、绘制、点击索引和残留选区防护不得直接删除。

验收：单条及批量操作不能改变导入项的正文、评论、颜色、样式、范围或存在性；云端同步仍可改变这些字段。关闭查看菜单后的残留选区不能影响本地书签或新增批注的归属。

## 第三阶段：确认本地操作及兼容范围

- 本地独立新增、编辑和删除高亮或评论正常，不带云端来源标记；关闭、重开以及云端更新后仍保留。
- 已有本地批注、旧适配器误标记但尚未丢失的书签、阅读进度均保留；不通过清空设置或重建整个 sidecar 实施限制。
- Browse、最近阅读、文件管理器以及相对和绝对路径打开同一受管 PDF 时采用同一边界。
- 普通 PDF、EPUB 和其他账号文件不受限制。采用当前 reader/document 实例的适配，避免修改全局类并影响下一本书。

本轮不增加“严格查看模式”。用户认可的默认策略允许本地独立批注；如果以后明确需要零本地笔记，再单独制定受管 PDF 禁止新建和修改本地批注的可选模式，并保留书签、进度和选择复制。

## 验证与交付

1. 增加与上述数据保护边界相称的回归测试，覆盖真实修改路径、混合批量操作、云端刷新及文件写入拦截；不为菜单文字等低影响变化单独编写实现镜像测试。
2. 使用官方 KOReader v2026.07.2 实际 Lua 模块验证批注详情、列表、批量操作、内嵌导入与文档切换。如果继续声明支持 v2026.03，也对该版本执行对应兼容检查。
3. 在 Kindle Oasis 3 上验证点击、长按、列表操作、书签、本地批注、进度恢复与 PDF MD5。源码接口测试不能代替硬件验收。
4. 更新 `docs/annotation-sync.md` 与 README，准确说明只读范围、本地保存位置、刷新时机及原文件保护。
5. 将实现完成的版本另行打包并记录校验值；与本次 `bookmark-fix` 包区分，便于实机比较和回退。

具体拦截点以原生写入路径审查和测试结果确定。这里的文件保护限定插件支持的 KOReader 操作，不扩展为对外部程序或任意第三方插件的文件访问控制。

## 实施记录

- 新增 `annotationpolicy.lua`，在受管文档实例拦截 `_checkIfWritable`、PDF 批注修改方法及 `writeDocument`，阻止关闭保存和内嵌批注导入；隐藏在 native 偏好之后的写入路径也被阻止。
- 统一来源判定复用 `annotations.lua` 的账号、附件和插件标记，并继续将书签排除在云端归属外。单条详情改用只读查看窗口，修改方法另有实际入口保护；混合列表操作保留云端行并报告跳过数量。
- 移除旧的 `extendSelection` / `addItem` 云端来源继承适配。绘制、排序、匹配、跨页点击及残留选区防护保留，本地原生扩展继续可用。
- 原生跨设备导入保留当前云端投影，仅处理本地项；无导入文件时保留原列表引用和排序，合法 Zotero 快照仍可增改删。
- 验证记录见 `annotation-sync.md`；实机操作见 `kindle-annotation-readonly-test.md`。本轮未修改设备，仓库提交与实机验收分别记录。
