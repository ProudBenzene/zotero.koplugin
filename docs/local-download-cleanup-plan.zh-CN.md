# 一键删除本机 Zotero 下载文件：实施计划

状态：2026-10-10 完成初版与宿主验证。用户实机测试出现“删除 1 份、跳过 5 份”，2026-10-11 已核对设备并修复文件身份判断；用户随后确认重试解决问题，已能完全删除本机文献。本次设备检查仅只读，未继续删除实际文献。

## 目标与范围

在 **Zotero → 维护** 增加 **删除所有本机下载的文献**。点按后展示可滚动的逐文件预览和统计，用户核对并确认一次，随后批量删除插件在本机下载的 PDF 和 EPUB。

用户已明确选择：**包含所有账户的插件下载**，不限于当前账户、当前分类或当前文献库列表。这里的“本机”指运行 KOReader 的设备，识别范围为插件使用的本地存储。

| 内容 | 计划行为 |
| --- | --- |
| 所有账户的受管 PDF、EPUB | 删除本地副本，包括待更新的旧副本 |
| 云端已删除附件、附件改名留下的本地文件 | 扫描存储目录并识别，不依赖它仍存在于当前文献库 |
| 下载校验收据、独立 PDF 批注缓存、相应临时缓存 | 清理已确认附件对应的数据 |
| KOReader 本地批注、书签、阅读进度、文档缓存 | 沿用单文件删除的清理语义；确认框明确说明 |
| 最近阅读、阅读收藏与书籍信息缓存 | 清理对应文件的引用和缓存 |
| Zotero 云端条目、附件、批注与 WebDAV 文件 | 保留；操作不发送网络请求 |
| 本地账户配置、主库 `library.json` | 保留；删除后仍可浏览和重新下载 |
| 当前正在阅读的目标文档 | 跳过并报告，关闭后可再次执行 |
| 无法确定归属的旧文件、用户额外放入的文件 | 保留并列出位置，不报告为已清空 |

旧版本共享目录不能可靠地将所有文件对应到附件。识别不清的旧文件是这项功能的边界，不能仅凭 `.pdf` 或 `.epub` 扩展名认领，也不能通过递归清空整个 `zotero/` 目录实现。

## 改动前的能力与缺口

- `main.lua` 的维护菜单只有全库重同步与强制批注刷新两个入口。
- `LocalFiles.getPDFPath/removePDF` 已实现单个当前账户 PDF 的本地删除：校验真实路径、拒绝删除正在阅读的文件，先定位文档设置，再删除文件及关联数据，最后清理历史与收藏。
- `API.storage_dir` 仅指向当前账户目录；本机全部账户需要从 `API.zotero_dir .. "/storage"` 扫描，不能通过切换账户来删除。
- `API.getItems()` 只表示当前账户的有效元数据。仅遍历它会漏掉其他账户、已删除云端条目及附件改名留下的副本。
- 现有 `.zotero-cache.json` 只有 `version` 与可选 `md5`，未记录文件名、账户和附件 key。历史下载需要兼容识别，后续下载需要留下更完整的归属记录。
- 当前单文件删除入口只支持 PDF，EPUB 尚需补齐。

## 实施顺序

### 1. 统一 PDF 与 EPUB 的单文件删除

在 `localfiles.lua` 抽出通用附件路径校验和删除方法，保留现有 PDF 方法作为兼容入口，避免改变现有调用者行为。

识别对象仍是插件下载的 `imported_file/imported_url` 附件。校验存储根、账户目录、附件目录和文件的实际路径，拒绝越界路径、符号链接及非普通文件。正在阅读的 EPUB 与 PDF 一样跳过。

继续通过 KOReader `DocSettings` 定位各类文档设置，包括文档旁目录、集中存储和哈希存储。必须在文件存在时完成定位；文件删除失败时保留其批注和阅读数据。

### 2. 建立覆盖所有账户的本地扫描

新增扫描函数，产出待删除清单与无法识别的残留清单。扫描不联网，且不要求 API 密钥仍有效或先完成同步。主库损坏时，只要存储根可用，也应能清理具有足够本地归属证据的下载。

依次使用以下证据识别文件：

1. 当前账户元数据和对应附件存储路径。
2. 完整下载收据中记录的账户、附件 key、文件名与格式，并核对目录一致性。
3. 历史收据结合独立附件目录中的文件。能唯一定位时纳入；多个候选时使用可用的收据 MD5 进一步识别，无法确认则报告为残留。

旧版本路径另做兼容识别；已有目录中的未知文件保留。需要包含待更新副本、可识别的改名前副本，以及已不在主库中的下载。不能只筛选状态恰好为 `downloaded` 的附件。

在 `zoteroapi.lua` 的成功下载收据中增加格式版本、插件来源、`user_id`、`attachment_key`、`filename` 和 `content_type`，保留原有 `version/md5`。可复用的旧下载在有可靠元数据时补齐收据，无需重新下载；旧收据仍可读取。

扫描结果记录每个文件的所属目录、真实路径、大小、内容 MD5 与诊断用的文件属性。确认后只删除这份清单，执行前重新核对路径、大小与内容；路径或内容改变时跳过，不自动扩大范围。新任务不再将 inode/ctime 完全相同作为删除条件，避免 FAT 文件系统元数据变化误报文献已变化。扫描和删除核对都按内容块分批调度。

### 3. 批量删除与残留清理

批量任务逐文件调用通用删除逻辑，不递归删除账户目录或附件目录。目录只在清理完成且为空时移除。

每个任务在删除前定位文档设置与已知缓存，并保存必要的待清理路径。文件删除成功后再清理附属数据；部分清理失败或程序中断时，保留本地任务记录，后续执行可继续清理已删除文件的残留，包括无法在文件消失后重新定位的哈希文档设置。任务记录的路径同样需要校验，不能作为任意文件删除指令。

失败不会终止其他附件的处理。分别统计：文件已删除、文件删除失败、正在阅读而跳过、身份不明而保留，以及附属数据尚未清理完成。只有全部目标处理成功且没有未识别残留时，才显示“已清空”。

### 4. 菜单、预览确认与进度

在 `main.lua` 加入维护入口和批量操作方法。扫描与删除分批调度，让数量较多时界面仍能更新；在 `progressdialog.lua` 增加扫描与删除阶段，沿用墨水屏刷新节流。

预览开头显示：

> 将删除本机所有账户的 Zotero 下载文件：X 个 PDF、Y 个 EPUB，文件大小约 Z。
>
> 同时删除这些文件的本地批注、书签和阅读进度。Zotero 云端数据会保留，可重新下载。
>
> 正在阅读及无法识别的文件会跳过。

按 2026-10-10 追加要求，确认界面使用可滚动的完整清单。按 2026-10-11 界面简化要求，每个目标仅列出文献题名（本地元数据可用时）、附件名称和完整本地路径，移除单独的文件名、格式、账户与附件 key 字段。这些信息可从路径中查看；其他账户或已移除元数据的下载用文件名显示。正在阅读的文件标明会跳过，已删除文件的重试项标明只清理残留数据，无法识别的保留位置也列在预览中。

按钮为“取消”和“删除所有本机下载”。取消、返回或关闭预览不删除文件，并释放共享操作状态。确认后仅处理预览中的清单，不扩大范围。无可删除文件时显示相应提示；若还有待清理的附属数据，则允许继续清理。

统一操作互斥，覆盖删除、下载、批注刷新、全库同步与账户切换，并在异常退出时释放状态。现有 `self.syncing` 和 `browser.downloading` 分属不同对象，需要一起处理。

删除完成后刷新文献库列表及必要的文件列表，使本地状态立即反映结果。已删除附件在插件内恢复为无本地副本；不会自动重新下载。

在 `i18n.lua` 增加中文文案，更新中英文 README 与 `docs/annotation-sync.md`，明确所有账户范围和本地阅读数据的删除语义。

### 5. 验证与交付

重点验证实际删除边界与失败处理：

- 多账户混合 PDF/EPUB、独立附件、多附件文献与待更新副本均能处理。
- 云端已删除条目、改名遗留文件及历史收据不被当前主库列表漏掉；无法确认的文件明确列为残留。
- 预览完整显示多账户文件及题名、附件名称、路径；取消、关闭预览、重复点击确认、无下载、无有效凭据、主库损坏、重复执行均得到正确结果。
- 正在阅读的 PDF/EPUB、符号链接、目录越界及确认后目标改变不会被删除。
- 文件删除失败保留阅读数据；附属数据清理失败单独报告，重新执行可继续清理。
- 账户配置与主库缓存保持原值，无网络请求；当前账户附件能重新下载并重新获取批注。
- 使用官方 KOReader v2026.07.2 的 `DocSettings` 验证 PDF/EPUB 的文档旁、集中与哈希设置清理，再在 Kindle Oasis 3 验收菜单、进度、部分失败和重新下载。

对应测试放入 `tests/downloadcleanup.spec.lua`、`tests/localfiles.spec.lua`、`tests/main.spec.lua`、`tests/i18n.spec.lua`，扩展原生 `tests/localfiles-integration.lua` 与真实 JSON 检查，并为扫描补齐真实目录枚举与符号链接检查。实施完成后运行与改动相称的离线回归和原生模块检查；设备验收状态单独记录。

## 现有重同步是否包含 PDF 批注

**包含强制重新获取已下载 PDF 的批注。** 根据 2026-10-10 的用户要求，全库重同步现已改为先全量同步主库，再强制重新获取批注。

| 入口 | 主库同步 | 已下载 PDF 批注 |
| --- | --- | --- |
| 同步 | 通常增量 | 按批注 key/version 与文件身份判断，补取缺失或变化的缓存 |
| 维护 → 重新同步整个文献库 | 强制全量 | 绕过变化判断，逐份强制重新获取 |
| 维护 → 重新获取已下载 PDF 的批注 | 通常增量 | 绕过变化判断，逐份强制重新获取 |
| 长按单个 PDF → 更新批注 | 不同步主库 | 强制重新获取这一份 PDF |

代码调用链：维护的全库重同步入口执行 `API.resetSyncState()`，然后调用 `Plugin:onZoteroSyncAction(true)`。该方法先执行 `API.syncAllItems()`，成功后再执行 `Annotations.refreshDownloaded(..., true)`。两个维护入口均绕过未变化缓存的复用；普通“同步”继续按变化判断。

主库同步失败时不进入批注刷新。批注仅针对当前账户、主库中仍存在且本地有副本的 PDF；不包含 EPUB、未下载附件或其他账户的下载。它们不会重新下载 PDF；缓存更新在下次打开 PDF 时应用。

变更前核对执行了 10 项相关现有离线测试，以及 1 项维护菜单调用链检查，共 **11 项通过**，用于确认当时的同步与删除行为。重同步调整增加同版本缓存也必须重新获取的回归，并验证两个维护入口获取失败时均保留旧缓存；该阶段完整离线回归 **166/166 通过**。

## 实施记录

- 新增 `downloadcleanup.lua`：按账户与附件目录扫描，使用当前元数据、完整收据、唯一历史候选或历史 MD5 识别文件；新收据保留已知旧文件名。扫描不切换账户，不联网，也不触发旧主库缓存的迁移或重写。
- `localfiles.lua` 提供 PDF/EPUB 共用路径校验、文档设置定位和清理；保留原有 PDF 方法。单文件详情页也支持 EPUB 删除。
- 每个附件目录的 `.zotero-cleanup.json` 保存删除前定位的文档设置和文件身份，失败后可重试；重试时限制为该文档的原生文档设置位置与 KOReader 文档缓存，拒绝任意外部路径。不会覆盖已被替换文档的未完成记录。
- `main.lua` 增加所有账户的维护入口、逐文件滚动预览、分批扫描/删除与完整结果列表。预览和结果保留实际题名及路径，界面文案支持中文。共享操作状态阻止下载、批注刷新、同步和账户切换与清理重叠；取消、关闭预览与错误均释放状态。
- 对正在阅读的文档，以及与其共用哈希文档设置或页面缓存的下载，均跳过。未知文件保留并列出。只删除已确认的文件，目录仅在为空时移除。
- 中英文说明与界面翻译已更新。验证结果与实机边界见 `docs/annotation-sync.md`；清理记录及下载收据均向后兼容。
- 2026-10-11 修正版改用确认前后内容核对，保留旧清理记录兼容，并记录具体跳过原因。设备文件的临时副本测试复现旧版“1 删除、5 跳过”，修正版在相同场景完整清理 6 份副本；原设备仅只读。详见 `docs/download-cleanup-device-check-2026-10-11.md`。
